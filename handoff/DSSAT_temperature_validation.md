## 3. 原 DSSAT 温度路径已经重新核对源码

官方 `dssat-csm-os` 源码链：

`WEATHR.for -> HMET.for -> HTEMP`

`HMET`/`HTEMP` 使用 Parton & Logan (1981) 型日变化重构。核心输入包括：

- 当日最高温 TMAX
- 当日最低温 TMIN
- 日长 DAYL
- 温度曲线系数 ATL / BTL / TAMP

源码中白天段主要为正弦型曲线，夜间段采用指数衰减连接。

重要澄清：

- DAYL 是 `HTEMP` 的直接输入，会直接改变逐小时温度曲线。
- SRAD 会进入 `HMET` 的辐射/能量相关计算，但没有作为 `HTEMP` 的直接输入。
- DTR = TMAX - TMIN（日较差），它属于我们进行极端温度/日较差判别时的派生量，不是 DSSAT 天气文件中额外要求用户提供的独立变量。

## 4. 版本隔离原则

DSSAT 官方当前 v4.8.6.0 release notes 已包含 `WEATHR.for` 的 monthly temperature amplitude calculation 修正。

因此主验证必须固定在 4.8.5：

- A：原始 DSSAT 4.8.5
- B：DSSAT 4.8.5 + 本研究最终温度修正

可选增加：

- C：官方 DSSAT 4.8.6.0，仅作为上游版本参考

C 不能代替 A/B，因为否则会把官方版本修正与本研究温度算法贡献混在一起。

## 5. 最终验证矩阵

### A. 原模型

- 原始 4.8.5 温度算法
- 原天气、土壤、品种、播期、灌溉、施肥参数

### B. 温度优化模型

- 仅替换/增加最终确定的温度重构与极端判别逻辑
- 其他输入与 A 完全一致

### 每个处理输出

1. 吐丝/开花日期（anthesis/silking）
2. 成熟日期（maturity）
3. 最终籽粒产量 HWAM
4. 若输出完整，再检查 LAI、生物量等过程变量，作为机制解释，不作为第一验收条件

### 汇总指标

- 每处理绝对误差
- Bias
- MAE
- RMSE
- Willmott d（与原项目历史指标保持一致）
- 优化前后变化：`Delta error = error_modified - error_baseline`

## 6. 判断优化是否有效

主要成功标准：

1. 6 个处理整体产量 RMSE 明显下降；
2. 吐丝/成熟期误差不出现系统性恶化；
3. 改善集中在高温、低温或大 DTR 条件下时，应与温度算法触发日相对应；
4. 普通温度日应尽量保持原 DSSAT 行为，避免为了少量极端日改善而改变整个生育季温度轨迹；
5. 若产量变化很小，需要定量说明原因：温度修改发生日数、发生生育阶段，以及这些日子是否落在开花/灌浆等温度敏感阶段。

## 7. 当前技术结论

现在需要验证的是“逐小时温度改善是否传递到作物层”。即使逐小时温度误差下降，如果触发日不在关键生育期，最终产量可能变化很有限；反之，开花和灌浆阶段少数极端日的修正也可能对产量产生明显影响。

因此最后结果必须形成一条完整证据链：

`极端日识别 -> 小时温度变化 -> 关键生育期温度暴露变化 -> 物候变化 -> 产量误差变化`
